# Значимый выбор модели

В upstream ADR сохраняет контекст трудного выбора. В Brain эту роль выполняет существующий раздел README «Решения».

Предложи развёрнуто зафиксировать архитектурный выбор, когда одновременно верны три условия:

1. Его дорого пересмотреть.
2. Без контекста будущему читателю будет непонятно, почему поступили так.
3. Были реальные альтернативы с различными последствиями.

Обычные факты и определения не становятся решениями ради заполнения формы. Записывай принятый выбор кратко; дополнительные последствия нужны, когда они меняют действия будущего исполнителя.

```markdown
**Р-n. Частичный возврат относится к строке заказа.**
Клиент может возвращать товар несколькими партиями. Связь со строкой позволяет
проверять остаток количества, не запрещая последующие возвраты.
**Отвергли:** возврат только целого заказа; он не покрывает согласованный сценарий.
**Пересмотреть если:** учёт товара перейдёт от строк к отдельным экземплярам.
```

Подходящие поводы: владение сущностью между контекстами, интеграция событиями вместо синхронного вызова, дорогой выбор хранилища, сознательное отклонение от очевидного подхода, ограничение партнёра, которого не видно в коде.

Сама лёгкость реализации не делает выбор архитектурно важным. Замена простой библиотеки обычно не требует развёрнутой записи. Изменение словаря без реального компромисса фиксируется определением.
