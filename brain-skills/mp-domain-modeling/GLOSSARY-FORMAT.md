# Определения в постановке

При фиксации уточнённого термина добавь компактный блок в подходящую часть README «Постановка». Не создавай отдельный словарь ради этого формата.

```markdown
### Термины: возвраты

Контекст: возврат товара после исполнения заказа.

**Возврат:** требование клиента вернуть переданное количество товара по строке заказа.
Не использовать как синонимы: отмена заказа, возврат платежа.

**Возврат платежа:** перечисление клиенту денег по подтверждённому возврату.
Не использовать как синоним: возврат товара.

Связь: один возврат может требовать нескольких возвратов платежа.
```

1. Определи, что представляет собой понятие, одним или двумя предложениями.
2. Из нескольких слов для одного понятия выбери одно. Остальные укажи как нежелательные синонимы, когда это предотвращает путаницу.
3. Включай предметные понятия проекта. Общие слова программирования, например таймаут или исключение, не добавляют предметной ясности.
4. Не помещай в определение технический план, состояние исследования или реализацию. Сценарии и требования живут рядом в постановке, технические выборы в «Решениях».
5. Группируй термины по контексту только при реальном различии контекстов. Для нескольких контекстов назови владельца сущности и связи: «Заказы передают событие исполнения в Расчёты; Расчёты владеют платежом».
6. Перед записью проверь существующий канон. Если определение уже существует, используй ссылку на него; не заводи конкурирующую копию.
