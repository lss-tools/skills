# Подмена зависимостей

Подменяй то, что пересекает границу системы: внешний платёжный или почтовый интерфейс, время, случайность, иногда файловую систему и БД. Для хранилища предпочитай реальную тестовую БД, когда она доступна и уместна. Внутренние модули проходят через настоящий вызов.

## Внедрить зависимость

```typescript
// Зависимость выбирается снаружи.
function processPayment(order, paymentClient) {
  return paymentClient.charge(order.total);
}

// Скрытое создание клиента затрудняет выбор тестового адаптера.
function processPaymentHidden(order) {
  const client = new StripeClient(process.env.STRIPE_KEY);
  return client.charge(order.total);
}
```

Такой интерфейс позволяет использовать реальный внешний адаптер в работе и конкретный тестовый адаптер в контуре. Не выноси точку подмены, если там ничего действительно не меняется; словарь и критерии находятся в mp-codebase-design.

## Конкретные операции вместо универсального fetch

```typescript
const api = {
  getUser: (id) => fetch(`/users/${id}`),
  getOrders: (userId) => fetch(`/users/${userId}/orders`),
  createOrder: (data) => fetch("/orders", { method: "POST", body: data }),
};

// Универсальная подмена вынуждает тест разбирать endpoint и options.
const genericApi = {
  fetch: (endpoint, options) => fetch(endpoint, options),
};
```

У конкретной операции один ожидаемый тип результата, меньше условной логики в настройке теста и яснее наблюдаемое действие. Пример показывает форму интерфейса; рабочая сериализация тела и обработка ошибок следуют контракту проекта.

Если подмена начинает воспроизводить всю внутреннюю реализацию, пересмотри выбранную поверхность проверки. Проверяй результат реального поведения, а не совпадение двух искусственных моделей.
