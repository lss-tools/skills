# Хорошие и плохие тесты

Примеры иллюстрируют публичную поверхность проверки. Они не предписывают язык или тестовый фреймворк проекта.

## Наблюдаемое поведение

```typescript
test("пользователь оформляет заказ с допустимой корзиной", async () => {
  const cart = createCart();
  cart.add(product);
  const result = await checkout(cart, paymentMethod);
  expect(result.status).toBe("confirmed");
});
```

Здесь проверяется нужный пользователю итог через интерфейс. Внутренние классы можно заменить, сохранив поведение и тест.

## Связь с внутренней реализацией

```typescript
// Плохой пример: утверждение о внутреннем вызове.
test("checkout вызывает обработчик платежа", async () => {
  const mockPayment = jest.mock(paymentService);
  await checkout(cart, payment);
  expect(mockPayment.process).toHaveBeenCalledWith(cart.total);
});
```

Признаки проблемы: подмена своих внутренних модулей, вызов приватного метода, утверждение о числе или порядке внутренних вызовов. После рефакторинга тест падает при сохранённом поведении. Число вызовов внешнего платёжного шлюза может быть частью публичного контракта идемпотентности; тогда проверяй именно этот контракт на подходящей точке подмены.

## Проверка через тот же интерфейс

```typescript
// Плохой пример: тест обходит публичный интерфейс чтения.
await createUser({ name: "Alice" });
const row = await db.query("SELECT * FROM users WHERE name = ?", ["Alice"]);
expect(row).toBeDefined();

// Хороший пример: новый пользователь доступен потребителю.
const user = await createUser({ name: "Alice" });
const retrieved = await getUser(user.id);
expect(retrieved.name).toBe("Alice");
```

Запрос во внутреннюю таблицу допустим для контракта самого хранилища, если именно он выбран публичной границей. В тесте пользовательской возможности такой запрос связывает проверку с хранением.

## Независимый эталон

```typescript
// Плохой пример: тест повторяет алгоритм реализации.
const items = [{ price: 10 }, { price: 5 }];
const expected = items.reduce((sum, i) => sum + i.price, 0);
expect(calculateTotal(items)).toBe(expected);

// Хороший пример: известный разобранный результат.
expect(calculateTotal([{ price: 10 }, { price: 5 }])).toBe(15);
```

Эталон берётся из постановки, известного корректного примера или независимой модели. Тождественное повторение вычисления закрепляет одинаковую ошибку в тесте и коде.

Перед добавлением теста ответь: какое изменение пользовательского поведения сделает его красным? Если ответ сводится к переименованию внутреннего метода, выбери другую поверхность проверки.
