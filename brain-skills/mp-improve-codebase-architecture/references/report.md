# Визуализация архитектурных кандидатов

Используй, если сравнение схем помогает выбрать направление. Сам отчёт остаётся в законном месте задачи; временный HTML Brain идёт в `D:/Brain/temp`. Файл не обязан открываться внешней командой: передай кликабельную ссылку.

## Карточка кандидата

1. Короткое название углубления предметного модуля.
2. Сила рекомендации: «сильная», «стоит исследовать», «предположение».
3. Категория зависимости из mp-codebase-design: внутри процесса, локально заменяемая, порты и адаптеры либо внешняя имитация.
4. Ссылки на файлы.
5. Центральная схема до/после.
6. По одному предложению о трении и изменении.
7. Конкретные выигрыши: «проверка одного интерфейса», «исправление в одном модуле», «удалены четыре передаточных модуля».
8. Предупреждение о конфликте с решением, когда пересмотр оправдан доказанным трением.

Заверши рекомендацией одного кандидата с причиной и ссылкой на его карточку. Схема должна читаться без поясняющего абзаца.

## Выбрать рисунок

1. **Граф вызовов:** покажи вызовы и красным выдели утечку знания через точку подмены. Подходит Mermaid flowchart; последовательность показывает сокращение шести обращений до одного.
2. **Сечение:** до изменения несколько тонких полос, после одна глубокая область со скрытым порядком действий.
3. **Масса интерфейса:** отдельные прямоугольники интерфейса и реализации. У мелкого модуля они сопоставимы; у глубокого интерфейс мал при большом скрытом поведении. Это иллюстрация отдачи, а не метрика строк кода.
4. **Свёртка дерева вызовов:** до несколько модулей, после их связи полупрозрачно внутри одного модуля.
5. **Произвольные блоки и стрелки:** CSS и SVG, когда автоматическая раскладка скрывает главный смысл.

Легенда: сплошной блок означает модуль, пунктир точку подмены, красная стрелка утечку знания, толстый тёмный блок глубокий модуль. Используй один акцентный цвет и свободное пространство. Цвет дополняет подпись, а не заменяет её.

Если нужен переносимый HTML, предпочитай встроенные стили и SVG. CDN из upstream не является обязательной зависимостью Brain. При выборе Mermaid укажи ограничения внешней загрузки. Не называй отчёт автономным, если он требует сеть.

## Пример

```text
До: Приём заказа → Проверка заказа → Хранение заказа
         └────────────────────────→ Расчёт цены
Вызывающий код знает порядок и правила цены.

После: Приём заказа [проверка + цена + хранение]
Вызывающий код знает вход и наблюдаемый результат.
```

Выигрыш описывай через локальность и отдачу: какие знания сосредоточены и сколько потребителей больше не несут их сами. Фраза «код стал чище» не объясняет пользу.
