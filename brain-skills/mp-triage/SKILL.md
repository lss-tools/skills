# Проверка заявки

Проверь, требуется ли работа и готова ли заявка для исполнителя. Результат проверки не подменяет штатное состояние задачи Brain.

## Рассуждение о готовности

Различай две категории: **дефект** нарушает обещанное поведение; **улучшение** добавляет или меняет поведение. Текущее поведение само по себе не определяет обещание: прочитай договорённости.

Для рекомендации используй состояния: нужна оценка, нужны сведения, готово агенту, нужен человек, работа не требуется. Это смысловая классификация, а не новые метки или значения статуса Brain. Статус меняется только штатным процессом в пределах поручения.

Если пользователь просит обзор очереди, покажи необработанные заявки, текущую оценку и ожидающие сведения с новыми ответами. В каждой группе сначала старые. Дай количество и одну строку на заявку. Не включай постороннюю очередь, если назван конкретный объект.

## Проверка конкретной заявки

1. Прочитай исходный запрос, комментарии и прежние выводы. Для предложенной правки прочитай также diff и замечания: запрос с готовым кодом всё ещё требует проверки цели и поведения.
2. Найди связанные открытые задачи по предметному понятию, а не только словам автора. Проверь, не реализовано ли поведение уже сейчас. Покажи места поиска и найденную реализацию.
3. Проверь прежние решения об отказе в связанных задачах и фактах. Используй [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md). Не путай реализованное, отклонённое и отложенное.
4. Дай предварительную рекомендацию: категория, смысловое состояние и основание. Различай установленный факт и гипотезу. Продолжай разрешённую проверку без нового согласования рутинных действий.
5. До интервью проверь основное утверждение. Для дефекта выполни шаги воспроизведения в доступном контуре; для diff проверь заявленный эффект подходящими командами. Результат: подтверждено с указанием пути поведения, не воспроизведено с условиями либо сведений недостаточно. Недоступность среды фиксируй как предел проверки.
6. Если требуются решения, прочитай [mp-grilling](../mp-grilling/SKILL.md) и [mp-domain-modeling](../mp-domain-modeling/SKILL.md). Уточняй по одному вопросу, сохраняя уже полученные ответы. Проверяемые факты устанавливай самостоятельно.
7. Зафиксируй итог в документах задачи:
   1. **Готово агенту:** подготовь бриф по [AGENT-BRIEF.md](AGENT-BRIEF.md) в README «Постановка».
   2. **Нужен человек:** тот же бриф с точной причиной: внешние полномочия, недоступное ручное действие или выбор владельца.
   3. **Нужны сведения:** в «Постановке» оставь установленное; в «Неизвестном» укажи конкретный недостающий факт и влияние.
   4. **Поведение уже реализовано:** дай ссылку на него. Это не отказ от функции.
   5. **Предложение отклонено:** запиши реальное решение с причиной и условием пересмотра в «Решениях».
   6. **Оценка не завершена:** сохрани частичный результат и следующий нужный факт, не объявляя готовность.

```text
заявка → дубль / готовое поведение / прежний отказ
       → проверка утверждения → уточнение → бриф или точный пробел
```

Явное поручение владельца определяет дальнейшее действие. Если он уже выбрал направление, не начинай заново согласование категории. Сам этот скил не разрешает закрывать задачи, отправлять сообщения или менять внешние метки.

## Продолжение и готовность

1. При возобновлении прочитай прежние выводы и новые ответы. Не задавай повторно решённые вопросы.
2. Обоснование категории, результат проверки и дальнейший исполнитель понятны.
3. Бриф содержит наблюдаемое поведение, проверяемые критерии и границы. Неизвестные сведения не выглядят подтверждёнными.
4. Исходная заявка остаётся контекстом; рабочий контракт содержится в единственном README задачи. Разбор ТЗ и стадии 1С сохраняются.
